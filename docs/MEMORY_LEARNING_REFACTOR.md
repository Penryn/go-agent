建议把记忆学习系统收敛为一条链路：**群聊证据 → 记忆声明 → 确认与纠错 → 有效记忆 → 按需回忆**。按目标模型进行破坏性重构，直接替换旧学习体系；PostgreSQL、Outbox、BM25 和 pgvector 中符合目标职责的基础能力可以继续使用。

重构约束：不保留旧接口、旧字段别名、旧工具参数、双写、旧表读取回退或自动兼容分支。开发可以分阶段，但上线只运行一套记忆逻辑。旧自动学习结果默认不作为新系统的可信记忆导入；有价值的内容从原始证据重新学习。

## 1. 对项目而言，学习应该改变什么

项目定位是长期生活在 QQ 群中的社交角色。记忆服务于下一次相处，学习应带来这些可观察的变化：

| 场景 | 期望行为 |
| --- | --- |
| 群友说过自己的偏好 | 在相关话题中自然记起，同时知道是谁、何时、在哪个群说的。 |
| 群友明确表达互动边界 | 下次行动前遵守，例如不再对该成员使用其拒绝的昵称。 |
| 大家形成群内梗 | 理解含义、适用情境和禁用情境，避免只模仿高频字串。 |
| 发生过一次有意义的互动 | 记住事件、参与者与结果，能分清“我参与过”和“我看到别人讨论”。 |
| 对方更正或偏好改变 | 新事实替代旧事实，历史仍可追溯，旧版本退出常规召回。 |
| 没有值得长期保存的信息 | 保留短期上下文即可，不产生长期记忆。 |

这里的“学习”是更新有证据的记忆和有限的互动偏好，不涉及模型训练、自动改系统提示词或自动扩充权限。

## 3. 模块职责与记忆分类

沿用有明确职责的包名，内部实现和接口按下表重写，不以旧代码结构限制新边界：

| 模块 | 唯一主要职责 |
| --- | --- |
| `application/learning` | 从已归档消息窗口、已归因反馈中提出声明，不直接写最终记忆。 |
| `application/memory` | 校验证据、合并声明、确认/拒绝/纠错/遗忘、装配记忆上下文。 |
| `application/retrieval` | 使用 BM25/vector/RRF 算法；按新记忆模型重写过滤、返回值和 trace 契约。 |
| `application/persona` | 拥有角色自身事实的真值与更新规则。 |
| `application/relationship` | 拥有关系事件及数值投影；记忆系统不写好感度最终值。 |
| `application/reflection` | 归因动作之后的反馈；只提交观察，不凭发送成功推导“大家喜欢”。 |
| `application/socialdecision` | 在行动前消费已确认的互动约束；不执行记忆正文中的任意指令。 |

通用记忆表先只保存三种类型，使用少量 subtype 区分具体用途：

| type | 示例 subtype | 内容要求 |
| --- | --- | --- |
| `semantic` | `member_preference`、`member_fact` | 关于明确主体的事实或偏好，例如“成员 42 自述更喜欢乌龙茶”。 |
| `social` | `group_culture`、`interaction_boundary` | 群内惯例、梗的含义或针对明确对象的互动边界，必须带适用条件。 |
| `episodic` | `shared_episode` | 有时间、参与者、事件经过和结果的一段经历；不为每条消息生成摘要。 |

这是对总架构文档中四类记忆方案的进一步收敛：`persona` 由 Persona Canon 提供只读事实视图，不再复制进通用 `memories`。学习发现角色自述时可以交给 Canon 校验，但不能借通用声明绕过其槽位、来源和成功发送要求。

短期话题、消息 burst 和未完成对话继续属于 Group Actor/GroupScene；它们只在形成值得回忆的完整事件后，才可能产生 episodic 声明。普通热词统计不单独成为一个长期记忆类型。

## 4. 统一声明与事实身份

### 4.1 区分“事实说的是谁”和“谁能看到”

`subject_kind/subject_id` 表示事实主体；scope 表示可见边界，两者不能互相代替。

- 第一阶段普通用户声明默认限于 `group:<gid>:user:<uid>`；群文化使用 `group:<gid>`。在线模型不能自行指定全局 scope。
- 同一个 QQ 用户在两个群的观察独立保存，不自动拼接跨群画像。
- 查询别人的事实不能只靠模型填写 user_id；未来若支持参与者检索，应由运行时提供经校验的主体集合。第一阶段沿用当前用户可见边界。
- 用户可见范围是检索边界，不是私聊通道；在群中回复仍需判断是否适合公开提及该事实。
- “群友 A 说 B 喜欢咖啡”保留 A 为发言来源、B 为候选主体，标为转述，不能当作 B 的本人确认。

声明按以下字段重新定义；删除旧结构中由新字段取代的表达，不同时保存新旧两套身份和来源字段：

| 字段组 | 内容 |
| --- | --- |
| 身份 | `claim_id`、`scope`、`subject_kind`、`subject_id`、`type`、`subtype` |
| 事实 | `predicate`、规范化 `value`、`content`、适用条件 `qualifier` |
| 来源 | `source_kind`、`extractor_version`、`evidence_event_ids`、可选 `action_id` |
| 生命周期 | `status`、`revision`、`decision_reason`、`decided_by`、`decided_at`、`memory_id` |
| 时间 | `first_observed_at`、`last_observed_at`、`expires_at` |

`confidence` 可以保留，但只作为辅助指标。模型自报的 0.95 不能替代证据校验或授权。

### 4.2 用事实键识别冲突，用声明键识别重复

```text
fact_key  = scope + subject_kind + subject_id + predicate + qualifier
claim_key = fact_key + normalized_value
```

先规范化再生成键，并对键加唯一约束。不要依赖完整自然语言正文或向量相似度决定事实身份。

例：`group:7:user:42 / user:42 / preferred_name / default` 只能有一个当前称呼；“喜欢乌龙茶”和“喜欢咖啡”则可以共存，不能因为 predicate 相同就互相覆盖。predicate 定义需要区分单值槽位和集合属性。无法归入有限槽位的描述保持 staged，或作为带时间的事件记忆，不强行生成任意键。

同义改写可以辅助匹配已有声明，但不同主体、范围或条件必须先硬分开。episodic 使用群、事件窗口标识和参与者标识确定身份，不能仅用摘要文本去重。

## 5. 证据、确认和纠错

### 5.1 所有入口使用同一证据校验

新建 `memory_claim_evidence(claim_id, event_id, evidence_role, ...)` 作为唯一证据关系表，替换 `learning_candidate_evidence` 和声明上的 JSON 证据数组；`(claim_id, event_id)` 唯一。接口可以返回证据 ID 列表，但不再持久化第二份计数来源。

校验由应用服务执行，不能只放在工具包装层：证据事件必须存在、位于声明允许的群和窗口内；发言人、时间、引用对象从归档读取，不能信任模型填值。在线证据还需属于本轮实际提供的上下文。反馈证据必须能关联到 action；模型摘要和 Bot 复述不能当作新的独立人类证据。

重复处理同一个事件不增加证据量。同一人刷十次、多人复制同一段话不等于十个独立确认；用于确认的依据应包含独立事件数、发言人数、会话窗口数和是否本人明确陈述。

证据不等于事实为真：“本人说过 X”与“X 已被外部验证”必须区分。图片描述和联网结果属于派生材料，保留来源，不用于自动确认某个群友的身份或偏好。

### 5.2 状态转换必须显式

```text
staged ──通过策略或人工审核──> confirmed ──明确纠正──> superseded
   ├──证据不成立/不应记忆──> rejected
   └──到期未确认─────────> expired

confirmed ──失效──> expired
confirmed ──撤销/忘记──> revoked
```

新增证据只能追加证据；不得通过普通 Upsert 把 rejected、revoked、superseded 改回 staged。重新审核使用显式操作和新的 revision，原决定保留。记忆有效状态由声明决定派生，后台不能独立把投影改成另一种状态。

确认时在同一 PostgreSQL 事务内完成：锁定声明/事实槽位 → 校验预期 revision → 更新审核决定 → 写有效记忆 → 失效被替代版本 → 投递向量任务。模型调用在事务外完成，事务只做本地校验和持久化。

### 5.3 默认确认策略

下面是首版规则，次数和时间值是待回放校准的初始值，不是已验证参数。

| 信息 | 首版处理 |
| --- | --- |
| 本人明确说“叫我阿青”“以后不要戳我” | 若指向 Bot、对象明确且属于允许的个人互动设置，可单次确认；只作用于该群该成员。 |
| 本人明确陈述普通兴趣/偏好 | 可形成带“本人自述”来源的记忆；否定、引用、玩笑或指代不清时保持 staged。 |
| 群梗和群惯例 | 至少 3 条独立证据、2 名成员、2 个会话窗口，并能解释含义与适用场景后再确认。 |
| 第三人评价某成员 | 默认不形成该成员的稳定事实；有价值时只记具体事件及转述关系。 |
| 一次共同经历 | 对事件事实可确认，不能从一次经历自动推出长期性格、关系或偏好。 |
| 健康、住址、账号秘密等个人信息 | 不进入默认自动长期学习；沿用明确的产品权限和保留策略。 |
| 群治理规则、工具权限或稳定角色设定 | 走既有管理权限/Persona Canon，不通过群内高频表达获得权限。 |
| 无人接话、发送成功、检索命中 | 只作观测，不形成正负关系结论或长期行为规则。 |

明确的当前停止请求应先由本轮决策处理，不能等待后台学习。可执行偏好只支持有限字段，例如 `allow_poke=false`、`preferred_name=阿青`；“晚上”这种时间未明确的描述不能自行猜成固定时段。未覆盖的自然语言偏好可作为有来源的软提示，不能转成代码、SQL 或系统指令。

纠错优先于一般学习：同一主体明确说“现在改叫阿岚了”，在验证单值槽位后替代旧值；两名群友说法冲突且来源强度相当时暂存争议，禁止自动最后写入者胜出。集合偏好则应区分新增与明确否定已有值。

## 6. 后台学习改为按会话窗口提炼

### 6.1 分开“生成候选”和“决定保存”

```text
归档增量 → 组装有限消息窗口 → 轻量筛选 → 结构化提炼
                                          ↓
在线声明入口（新契约）──────────────────> 同一声明服务
已归因 action_feedback ────────────────> 同一声明服务
                                          ↓
                               证据合并、确认、纠错
                                          ↓
                              有效记忆与可执行偏好
```

提炼输入包含群、时间、发言人、被引用消息、可见参与者、必要的近期上下文与相关已有声明。模型只返回事实主体、谓词/值、内容、证据 ID 和是否存在纠正；禁止输出数据库状态或最终关系分数。

轻量筛选用于排除纯通知、空消息和没有新信息的重复。删除现有 n-gram 学习器、话题后缀和行为词前缀判定，不将它们包成新接口继续使用。结构化提炼使用现有模型接入，首版无需增加模型供应商或独立 Agent。

初始窗口可按同群最多 60 条消息、15 分钟上下文、连续空闲 2 分钟闭合。按引用关系优先串联；跨窗口引用需要补回原消息，同群并行话题不能因为时间接近就被合成一个事件。窗口尾部保留有限重叠，证据唯一约束防止重复累计。

无值得保存的信息时输出空列表即为正常结果。模型失败、超时或结构不合法时通过 Outbox 重试，不能把未完成的窗口当成“没有事实”推进水位。限制单群任务时长和模型调用量，前台回复优先；失败和积压可在后台查看。

### 6.2 水位、晚到消息与重放

重建 `learning_watermarks` 为按归档序号和提炼版本记录进度的新结构；Outbox 继续承担任务投递。周期扫描负责补偿；每次任务可连续处理多个 200 条分页，在达到任务预算后立即投递续跑，不能固定再等 6 小时。旧的发生时间水位不转换成新序号，历史重学使用显式指定的证据区间。

消费顺序应使用每群归档序号 `archive_seq`，事件发生时间只用于语义排序。所有同群归档写入在短数据库事务内取得同一事务锁后分配序号、落库并提交；只有释放锁后下一事务才能分配，避免直接用普通自增 ID 的“先分配后提交”乱序漏洞。重复平台事件保留原序号；实质纠正应以新事实记录进入流。此项需要和负责入站模块的 agent 对齐，不能由学习模块擅自假设已有保障。

提炼前读取一个固定的水位区间；提炼完成后，用预期水位/revision 校验，在同一事务内保存该批声明及证据、投递确认任务、推进水位和安排续跑。另一个 worker 已推进时放弃过期提交并重新读取，不持有数据库锁等待模型。

水位表示“这批事件已完成声明提取”，不表示声明已通过审核。没有新消息时，确认/过期/人工审核任务仍须独立工作。声明与后续任务必须原子落库，避免水位已前进而候选永久无人处理。

重放同一窗口和提炼版本不得重新执行已完成的决定；Outbox 的幂等键与业务唯一键共同保障。需要更换提炼策略重新学习时显式改变版本，仍不得把相同证据重复计数。

## 7. 回忆应按用途装配

保留 RRF 算法和两轨降级能力，直接将记忆读取契约改为带有效性过滤的 `MemoryBundle`。同步修改 Context、工具和主动回忆的调用方，删除 `RelevantMemories` 裸列表契约及其旧 Prompt 拼接逻辑，不提供旧返回值适配器。

| Bundle 分区 | 查询方式 | 用途 |
| --- | --- | --- |
| `interaction_boundaries` | 按当前群和目标成员精确读取 | 行动前约束，不能依赖文字相似度或被普通 TopK 挤掉。 |
| `target_user_facts` | 当前主体与本轮问题相关的事实 | 避免忘记称呼、混淆成员偏好。 |
| `group_culture` | 当前话题下的群文化/梗解释 | 帮助理解语境，不强制模仿口癖。 |
| `relevant_episodes` | 当前话题相关的过往事件 | 支持自然续聊和共同回忆。 |

查询优先使用当前 burst 的完整意思、被引用文本和当前话题；“对”“那个呢”不能只按最新两个字检索。素材必须来自运行时上下文，不能为了召回而推测身份或跨群扩大范围。

每个条目携带 memory/claim ID、revision、主体、scope、内容、来源性质、证据引用、有效期和召回原因。预算裁剪按业务优先级与相关性处理，不能把已有排序的记忆列表当时间序列裁剪。角色自身事实仍由 PersonaContext 独立提供。

所有入口——自动上下文、`query_memory`、主动回忆、后台检索预览——共享相同有效性和可见性过滤。被拒绝、撤销、过期、被替代的记录不能参与常规召回；向量表与事实表关联时还应验证 source revision 一致。向量缺失或陈旧时走词法轨道，不能拿旧向量当当前内容的相似度依据。

群友没在相关话题上互动时，不为了证明“我记得”而主动翻出个人信息。主动回忆比被动回答采用更严格的相关性与适用场景判断。

### 7.1 使用统计不能充当事实证据

把现有 recall 拆清含义，优先扩展已有 trace，无需为每种统计新建表：

- `retrieved`：检索返回过，工具试探查询也计入。
- `included`：经过预算裁剪后实际提供给模型。
- `cited`：规划结果声明使用了某条记忆；这只是模型自报。
- `feedback_linked`：成功发送后有可归因的认可、纠正等证据。

只检索到或加入 Prompt 不能增加事实置信度、刷新证据时间或延长 TTL。使用效果也不能自动升级事实真实性；只有新的原始证据或审核决定可以改变事实状态。

## 8. 遗忘、版本与持久化

记忆相关 schema 按目标模型重写。下列名称是目标表，可沿用表名但不保留旧行结构和旧读写接口；不以追加大量可空兼容列替代重建：

| 表 | 调整 |
| --- | --- |
| `messages` | 继续保存证据；补可靠归档顺序，保留事件发生时间；不要求先重命名为 conversation_events。 |
| `memory_claims` | 重建统一声明；主体/事实键、真实有效期、审核原因、revision 和 memory 关联采用新约束。 |
| `memory_claim_evidence` | 新的证据去重和来源角色权威表；旧候选证据表退出运行。 |
| `memories` | 重建为已确认声明的读取投影；以有效状态、claim 关联和最后证据时间为准。 |
| `memory_vectors` | 从新记忆重新生成；校验源版本，支持失效清理，不导入旧向量。 |
| `learning_watermarks` | 新的归档序号、提炼版本与 revision；删除基于 occurred_at/event_id 的学习游标契约。 |
| `async_outbox` | 保留通用任务设施，新 handler 只接受新 payload；旧学习任务不交给新 handler 解析。 |
| `retrieval_traces` | 新记忆检索使用 included 条目、版本和反馈关联的新契约；旧 trace 仅作历史运维记录。 |

保留原始观察时间，不用任务执行时间把旧事伪装成新近事实。`last_observed_at` 只能由新的有效原始证据更新；索引重建、后台重试和普通读取都不得刷新它。

建议的初始有效期：未确认观察 7 天，群梗 30 天，普通偏好 90 天，事件记忆 180 天。已有明确日期的事实按实际日期失效；明确的“不再戳我”等互动边界保留到本人撤销或被明确替代，不能因为自然衰减又恢复打扰。以上默认值需要回放与运营反馈校准；无效 TTL 配置应报错，不能退成永久有效。

遗忘分两步：先在事务中撤销声明、禁用投影并产生清理任务，使所有读取立即失效；再异步清理向量和派生缓存。PromptSession 中已缓存的旧记忆也必须失效或重建，不能只过滤下一次查询。清理与迟到的索引任务使用同一记忆版本/状态检查，禁止已撤销内容被重新索引恢复。

用户明确要求忘记时，还应防止后续重放原始消息再次学回：保存最小的禁止重学标识，排除相应证据，并清理声明、缓存及含内容的任务 payload。保留原始群消息与否由消息保留策略决定；“退出回忆”与“彻底删除原始记录”在后台操作中分别说明，不能把逻辑失效宣传成物理删除。

## 9. 与另一 agent 的接口约定

目前工作区已有 `domain/feedback` 和 `application/reflection` 文件，但检查到的 App 组装仍未调用新的 FeedbackCollector；分类器也仅区分“无事件/有事件”。因此本方案不把反馈闭环列为已具备能力，不依赖这些类型的当前具体字段。

需要对齐四个边界：

1. **入站归档**：提供稳定事件 ID、群内可靠归档顺序和按 ID 查询证据的能力。
2. **反馈输入**：提供已持久化的 action/decision ID、Bot 实际平台消息 ID、响应人、证据事件及归因理由；窗口里有人聊天不能直接算对 Bot 的反馈。多人多动作交错时，只接受可明确关联的证据；无法关联则保留未知。
3. **角色与关系**：角色事实通过 Canon 处理；关系事件独立更新投影。记忆可以保存事件叙述，但相同 action/event 不应通过两个入口重复增加关系分值。
4. **决策与计划**：决策器消费有限的个人互动约束；ResponsePlan 或在线声明工具必须提交同一种新声明输入。同步修改当前调用方，不保留旧工具参数解码、旧 MemoryRecord 到新对象的运行时转换。此契约可以先完成，不必等待回复 Planner 的其他重构项。

### 9.1 删除与替换清单

| 删除的旧逻辑 | 目标替代 |
| --- | --- |
| `LearningCandidate`、`LearningCandidateStore`、`learning_candidates`、`learning_candidate_evidence` | 统一 Claim、证据关系和审核决定。 |
| `WriteIntent`、`MarkIntent`、`applyLearning`、业务层任意调用 `UpsertMemory` | 唯一的声明确认事务生成记忆投影；存储写方法只在该事务内部使用。 |
| `extractNgrams`、`topicSuffixes`、`behaviorSignal` 及仅凭 0.7 阈值晋升 | 窗口提炼、原始证据校验和按信息类别确认。 |
| `ThoughtRecord → BehaviorSignal → 长期行为记忆` | 有动作归属和人类证据的反馈输入；技术结果只作观测。 |
| 旧 `group_slang/user_catchphrase/topic_keyword/reaction_pattern/behavior_*` 记忆类型 | semantic/social/episodic 及有限 subtype；旧类型不作为别名接收。 |
| 通用记忆中的 `persona` 类型 | Persona Canon 独立真值和 PersonaContext。 |
| 当前 `ClaimInput`、工具参数与旧 `MemoryRecord` 返回值 | 按主体、scope、事实键和证据定义的新契约；全部调用方一次修改。 |
| `RelevantMemories` 与旧记忆 Prompt 拼接 | 分用途、带版本和来源的 MemoryBundle。 |
| 旧 TTL 类型映射、兼容 payload、过时测试断言 | 新配置、新任务格式和行为验收测试；旧配置启动时明确报错。 |

保留不依赖旧语义的算法测试，例如 RRF 排序和跨群不可见测试；把断言“刷词即可学会”“sent 可变成行为记忆”的测试直接删除并重写成目标行为测试，不通过兼容分支让旧断言继续成立。

反馈到记忆的默认规则：明确纠正指向对应事实；明确拒绝某种互动指向个人边界；感谢或接话可支持一次 episodic 事件。没有回应、话题转移或其他人继续聊天均不推出“对方讨厌我”或“这个群喜欢这种回复”。

## 10. 实施顺序与验收

所有阶段均为 `[未开始]`，表示本专项方案尚未实施；并非否认现有基础设施已存在。

| 阶段 | 工作与删除项 | 完成标准 |
| --- | --- | --- |
| P0：重写领域与契约 | 定义新 Claim、证据、投影与 Bundle；重建 schema/repository；删除旧候选和直接写记忆契约，同步修改工具、Context、配置和调用方。 | 同群两人同表达不覆盖；个人边界不升级全群；编译和运行路径中不存在旧学习逻辑。 |
| P1：确认、纠错与遗忘闭环 | 增加确认/拒绝/替代/撤销事务；过滤失效投影和缓存；增加声明审核与证据后台。 | 更正后各读取入口只见新版本；拒绝/遗忘不会被重放复活；崩溃不产生半个审核决定。 |
| P2：窗口学习与可靠追赶 | 实现新的窗口提炼器、归档顺序、水位事务和有界续跑；新输入直接提交统一声明。 | 小窗口不遗漏，超过 200 条能继续追赶；晚到事件不漏；模型故障不跳过水位；重复窗口不重复累计。 |
| P3：回忆策略与反馈联调 | 完成 Bundle 分区预算、边界精确读取和反馈联调；补充 included/反馈观测与中文回放集。 | 称呼与边界不被 TopK 挤掉；代词/短回复能依上下文召回；无关记忆不强行使用。 |

P0 与 P1 是第一个可交付闭环：一条声明能带着证据进入审核、成为记忆、被召回、被纠正或忘记。开发阶段允许停用后台学习功能，不保留旧学习器兜底；完整上线前再验收 P2 与 P3。不能只新增结构体、表和 Prompt 文本就标记完成。

上线采用一次切换：停止旧记忆相关 worker，终止或排空在途任务，取消旧学习/索引任务；离线归档需要保留的原始证据与人工校验记录；替换 schema、代码、配置和 PromptSession；从新空投影启动并按选定证据范围重学、重建向量。新运行时不读取旧候选、旧记忆或旧向量，也不提供自动回退。人工校验记录如需导入，使用一次性离线脚本进入新声明审核流程，完成后移除脚本，不建设长期迁移适配层。

旧表默认退出目标 schema，旧自动学习结果不要求搬迁。原始消息、人工记录及其他模块数据的清理范围在实施切换时单独明确；本次仅给出方案，不执行数据库删除。

验收用真实群聊的脱敏片段建立小型回放集，并优先覆盖以下情况：

| 用例 | 必须满足 |
| --- | --- |
| 两个用户都说“离谱” | 不共用主体记忆；不自动生成没有含义的长期事实。 |
| 一条消息刷十遍同一短语；或重放同一批任务 | 不按十条独立证据晋升。 |
| A 引用 B 的话、第三人开玩笑、Bot 复述群友原话 | 识别来源，不混淆本人自述、转述和 Bot 输出。 |
| “今晚别 @ 我”与“以后不要戳我” | 一个按日期失效，另一个持续到撤销；都只作用于正确对象。 |
| 偏好更新、同名不同人、跨群同一人 | 主体和作用域不串；单值替代与多值共存正确。 |
| 旧向量任务晚到、发送会话缓存未清、忘记后重放 | 被替代或撤销的内容不能复活。 |
| 第 201 条消息、晚到旧时间消息、两个 worker 并发、提交中断 | 不漏证据、不倒退水位、不产生重复确认。 |
| 发送后别人聊别的话题，或有人引用并纠正 Bot | 前者为未知/无明确反馈；后者才成为对应事实的纠错证据。 |

质量评估分开看：声明正确率和主体/范围准确率、确认错误率、纠错/遗忘生效情况、Relevant Recall@K 与实际入 Prompt 的正确性、无关记忆占比、学习积压时间和每千条消息模型成本。先记录基线，再据回放调整窗口、TTL 和检索权重；不拿“写入记忆数量更多”当作学习进步。

第一版不引入图谱、强化学习、跨群人格画像合并、额外缓存层、reranker 或大规模中文索引替换。先让有限记忆有证据、能使用、能纠错；索引扩容继续按 [RAG_REFACTOR.md](/Users/admin/Desktop/go-agent/docs/RAG_REFACTOR.md) 的实际规模和评测结果推进。
