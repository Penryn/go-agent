状态：`[修订方案，未实施]`。本次核对新角色、决策和反馈链路并修改设计文档，不修改运行代码。

核对基线：2026-09-08 当前工作区。新模块已由 App 注入 Group Actor；按实际调用链区分“已有模块”“已接入”和“形成可靠闭环”。定向运行 PersonaContext、DecisionEngine、ResponsePlanner 和 Feedback 测试，4 个包共 22 项通过；这些测试未覆盖 App 的真实记忆接入、反馈时间区间和发送后持久化，不作为完整验收依据。

建议把记忆学习系统收敛为一条链路：**群聊证据 → 记忆声明 → 确认与纠错 → 有效记忆 → 按需回忆**。按目标模型进行破坏性重构，直接替换旧学习体系；PostgreSQL、Outbox、BM25 和 pgvector 中符合目标职责的基础能力可以继续使用。

重构约束：不保留旧接口、旧字段别名、旧工具参数、双写、旧表读取回退或自动兼容分支。开发可以分阶段，但上线只运行一套记忆逻辑。旧自动学习结果默认不作为新系统的可信记忆导入；有价值的内容从原始证据重新学习。

本次修订纠正六点：长期记忆不统一按 90/180 天失效；长期事实、近期状态与召回热度分开；记忆接到当前真实回复链路；反馈先完成归因与持久化再供学习；人物事实保留 Canon 的来源与裁决语义；记忆主体不再沿用旧 scope 中的当前发言人限制。

## 1. 对项目而言，学习应该改变什么

项目定位是长期生活在 QQ 群中的社交角色。记忆服务于下一次相处，学习应带来这些可观察的变化：

| 场景 | 期望行为 |
| --- | --- |
| 群友说过自己的偏好 | 在相关话题中自然记起，同时知道是谁、何时、在哪个群说的。 |
| 群友明确表达互动边界 | 下次行动前遵守，例如不再对该成员使用其拒绝的昵称。 |
| 大家形成群内梗 | 理解含义、适用情境和禁用情境，避免只模仿高频字串。 |
| 发生过一次有意义的互动 | 记住事件、参与者与结果，能分清“我参与过”和“我看到别人讨论”。 |
| 对方更正或偏好改变 | 新事实替代旧事实，历史仍可追溯，旧版本退出常规召回。 |
| 没有值得长期保存的信息 | 保留短期上下文即可，不产生长期记忆。 |

这里的“学习”是更新有证据的记忆和有限的互动偏好，不涉及模型训练、自动改系统提示词或自动扩充权限。

## 3. 模块职责与记忆分类

沿用有明确职责的包名，内部实现和接口按下表重写，不以旧代码结构限制新边界：

| 模块 | 唯一主要职责 |
| --- | --- |
| `application/learning` | 从已归档消息窗口、已归因反馈中提出声明，不直接写最终记忆。 |
| `application/memory` | 拥有长期事实及其生命周期，装配 MemoryBundle，提供按主体精确读取的互动约束。 |
| `application/retrieval` | 提供 BM25/vector/RRF 候选；只负责检索算法和 track trace，不承担人物理解或 Bundle 业务分区。 |
| `application/persona` | 拥有角色自身事实的真值与更新规则。 |
| `application/relationship` | 拥有关系事件及数值投影；记忆系统不写好感度最终值。 |
| `application/reflection` | 持久化并归因动作之后的反馈；供学习、关系和状态服务各自消费，不凭发送成功推导“大家喜欢”。 |
| `application/socialdecision` | 在行动前消费已确认的互动约束；不执行记忆正文中的任意指令。 |

通用记忆表先只保存三种类型，使用少量 subtype 区分具体用途：

| type | 示例 subtype | 内容要求 |
| --- | --- | --- |
| `semantic` | `member_preference`、`member_fact` | 关于明确主体的事实或偏好，例如“成员 42 自述更喜欢乌龙茶”。 |
| `social` | `group_culture`、`interaction_boundary` | 群内惯例、梗的含义或针对明确对象的互动边界，必须带适用条件。 |
| `episodic` | `shared_episode` | 有时间、参与者、事件经过和结果的一段经历；不为每条消息生成摘要。 |

这是对总架构文档中四类记忆方案的进一步收敛：`persona` 由 Persona Canon 提供只读事实视图，不再复制进通用 `memories`。学习发现角色自述时可以交给 Canon 校验，但不能借通用声明绕过其槽位、来源和成功发送要求。

角色的共同经历仍属于长期 episodic，例如“我和群友一起讨论过这场比赛”；只将稳定背景、自我设定和需要保持唯一性的角色事实交给 Canon，不能把“persona 类型归 Canon”误解为不再保存角色经历。

事实、关系与状态分别只有一个写入责任方：记忆服务保存“成员明确拒绝被戳”；关系服务决定是否增加 friction；角色服务决定当下耐心和精力。一次负面反馈不能被学习器、关系服务、PersonaAssembler 各自计算一遍同一状态。称呼等需要严格遵守的字段由记忆事实派生读取；短期情绪和群姿态不复制成第二份长期事实。

短期话题、消息 burst 和未完成对话继续属于 Group Actor/GroupScene；它们只在形成值得回忆的完整事件后，才可能产生 episodic 声明。普通热词统计不单独成为一个长期记忆类型。

## 4. 统一声明与事实身份

### 4.1 区分“事实说的是谁”和“谁能看到”

`subject_kind/subject_id` 表示事实主体；scope 表示可见边界，两者不能互相代替。

- 默认 scope 为当前群，主体由独立字段指明。来源是该群公开消息的事实，可以在同群相关对话中检索；需要额外限制披露的事实单独携带可见性条件。在线模型不能自行扩大 scope 或移除来源限制。
- 同一个 QQ 用户在两个群的观察独立保存，不自动拼接跨群画像。
- Runtime 根据当前参与者、明确提及者和引用原消息提供目标主体集合。这样 A 询问“小王上次说喝什么”时，可以回忆小王在同群公开说过的偏好；不再将旧“只能检索当前发言人”的规则当成目标需求。
- 用户可见范围是检索边界，不是私聊通道；在群中回复仍需判断是否适合公开提及该事实。
- “群友 A 说 B 喜欢咖啡”保留 A 为发言来源、B 为候选主体，标为转述，不能当作 B 的本人确认。

声明按以下字段重新定义；删除旧结构中由新字段取代的表达，不同时保存新旧两套身份和来源字段：

| 字段组 | 内容 |
| --- | --- |
| 身份 | `claim_id`、`scope`、`subject_kind`、`subject_id`、`type`、`subtype` |
| 事实 | `predicate`、规范化 `value`、`content`、适用条件 `qualifier` |
| 来源 | `source_kind`、`extractor_version`、`evidence_event_ids`、可选 `action_id` |
| 生命周期 | `status`、`revision`、`decision_reason`、`decided_by`、`decided_at`、`memory_id` |
| 时间 | `first_observed_at`、`last_observed_at`、可选 `valid_until`、可选 `review_after`；staged 另有 `staging_deadline` |

`confidence` 可以保留，但只作为辅助指标。模型自报的 0.95 不能替代证据校验或授权。

### 4.2 用事实键识别冲突，用声明键识别重复

```text
fact_key  = scope + subject_kind + subject_id + predicate + qualifier
claim_key = fact_key + normalized_value
```

先规范化再生成检索/去重键。claim_id 标识一次具体断言，不能把 `claim_key` 设为终身唯一：旧偏好被替代后，本人可能再次明确选择相同值。相同证据的重放合并进原声明；新的明确改回产生新声明，并保留时间和替代关系。单值属性对当前有效 fact_key 加唯一约束；集合属性只对当前有效的 `(fact_key, value)` 去重。

例：`group:7 / user:42 / preferred_name / default` 只能有一个当前称呼；“喜欢乌龙茶”和“喜欢咖啡”则可以共存。只对需要执行约束、唯一值或明确纠错的事实使用有限 predicate；普通经验允许保存带主体、时间、证据的自然语言摘要，不强迫所有长期记忆进入键值槽位。

同义改写可以辅助匹配已有声明，但不同主体、范围或条件必须先硬分开。episodic 优先使用原始事件锚点、群和参与者确定身份；提炼窗口是任务边界，不是记忆身份，否则调整窗口或重叠处理就会生成重复经历。跨窗口增补同一经历时合并证据。

## 5. 证据、确认和纠错

### 5.1 所有入口使用同一证据校验

新建 `memory_claim_evidence(claim_id, event_id, evidence_role, ...)` 作为唯一证据关系表，替换 `learning_candidate_evidence` 和声明上的 JSON 证据数组；`(claim_id, event_id)` 唯一。接口可以返回证据 ID 列表，但不再持久化第二份计数来源。

校验由应用服务执行，不能只放在工具包装层：证据事件必须存在、位于声明允许的群和窗口内；发言人、时间、引用对象从归档读取，不能信任模型填值。在线证据还需属于本轮实际提供的上下文。反馈证据必须能关联到 action；模型摘要和 Bot 复述不能当作新的独立人类证据。

重复处理同一个事件不增加证据量。同一人刷十次、多人复制同一段话不等于十个独立确认；用于确认的依据应包含独立事件数、发言人数、会话窗口数和是否本人明确陈述。

证据不等于事实为真：“本人说过 X”与“X 已被外部验证”必须区分。图片描述和联网结果属于派生材料，保留来源，不用于自动确认某个群友的身份或偏好。

### 5.2 状态转换必须显式

```text
staged ──通过策略或人工审核──> confirmed ──明确纠正──> superseded
   ├──证据不成立/不应记忆──> rejected
   └──到期未确认─────────> expired

confirmed ──失效──> expired
confirmed ──撤销/忘记──> revoked
```

新增证据只能追加证据；不得通过普通 Upsert 把 rejected、revoked、superseded 改回 staged。重新审核使用显式操作和新的 revision；每次决定追加到 `memory_claim_decisions`，保留前后状态、理由、操作者和时间。该表只审计生命周期，不记录每次读取。记忆有效状态由声明决定派生，后台不能独立把投影改成另一种状态。

确认时在同一 PostgreSQL 事务内完成：锁定声明/事实槽位 → 校验预期 revision → 追加审核决定并更新状态 → 写有效记忆 → 失效被替代版本 → 投递向量任务。决定以声明 ID、revision 和操作 ID 去重。模型调用在事务外完成，事务只做本地校验和持久化。

### 5.3 默认确认策略

下面是首版规则，次数和时间值是待回放校准的初始值，不是已验证参数。

| 信息 | 首版处理 |
| --- | --- |
| 本人明确说“叫我阿青”“以后不要戳我” | 若指向 Bot、对象明确且属于允许的个人互动设置，可单次确认；只作用于该群该成员。 |
| 本人明确陈述普通兴趣/偏好 | 可形成带“本人自述”来源的记忆；否定、引用、玩笑或指代不清时保持 staged。 |
| 群梗和群惯例 | “某成员解释过这个梗”可作为有来源的观察保存；“全群普遍如此”需跨成员、跨场景证据。3 条事件/2 名成员/2 个窗口仅用于首轮评测起点，不能硬编码为一切群文化的准入条件。 |
| 第三人评价某成员 | 默认不形成该成员的稳定事实；有价值时只记具体事件及转述关系。 |
| 一次共同经历 | 对事件事实可确认，不能从一次经历自动推出长期性格、关系或偏好。 |
| 健康、住址、账号秘密等个人信息 | 不进入默认自动长期学习；沿用明确的产品权限和保留策略。 |
| 群治理规则、工具权限或稳定角色设定 | 走既有管理权限/Persona Canon，不通过群内高频表达获得权限。 |
| 无人接话、发送成功、检索命中 | 只作观测，不形成正负关系结论或长期行为规则。 |

明确的当前停止请求应先由本轮决策处理，不能等待后台学习。可执行偏好只支持有限字段，例如 `allow_poke=false`、`preferred_name=阿青`；“晚上”这种时间未明确的描述不能自行猜成固定时段。未覆盖的自然语言偏好可作为有来源的软提示，不能转成代码、SQL 或系统指令。

纠错优先于一般学习：同一主体明确说“现在改叫阿岚了”，在验证单值槽位后替代旧值；两名群友说法冲突且来源强度相当时暂存争议，禁止自动最后写入者胜出。集合偏好则应区分新增与明确否定已有值。`confirmed` 表示来源和内容达到当前记忆策略，并不把“本人自述/成员转述”升级成客观验证事实；通常自动处理，只有争议和需授权事项进入人工审核。

## 6. 后台学习改为按会话窗口提炼

### 6.1 分开“生成候选”和“决定保存”

```text
归档增量 → 组装有限消息窗口 → 轻量筛选 → 结构化提炼
                                          ↓
在线观察提交（独立于是否回复）──────────> 同一声明服务
已归因 action_feedback ────────────────> 同一声明服务
                                          ↓
                               证据合并、确认、纠错
                                          ↓
                              有效记忆与可执行偏好
```

提炼输入包含群、时间、发言人、被引用消息、可见参与者、必要的近期上下文与相关已有声明。模型只返回事实主体、谓词/值、内容、证据 ID 和是否存在纠正；禁止输出数据库状态或最终关系分数。

三条路径共享校验而不共享“必须回复”的前提：群友原话在入站归档后即可形成声明，Bot 沉默或发送失败不应阻止记住它；Bot 自己声称的新设定必须等待成功发送并通过 Canon；动作效果与共同互动结果必须等待已归因反馈。在线观察可随当前回合提交，也可由后台窗口补提；不能只靠回复模型主动调用工具，否则沉默期间永远学不到群文化。

轻量筛选用于排除纯通知、空消息和没有新信息的重复。删除现有 n-gram 学习器、话题后缀和行为词前缀判定，不将它们包成新接口继续使用。结构化提炼使用现有模型接入，首版无需增加模型供应商或独立 Agent。

初始窗口可按同群最多 60 条消息、15 分钟上下文、连续空闲 2 分钟闭合。按引用关系优先串联；跨窗口引用需要补回原消息，同群并行话题不能因为时间接近就被合成一个事件。窗口尾部保留有限重叠，证据唯一约束防止重复累计。

无值得保存的信息时输出空列表即为正常结果。模型失败、超时或结构不合法时通过 Outbox 重试，不能把未完成的窗口当成“没有事实”推进水位。限制单群任务时长和模型调用量，前台回复优先；失败和积压可在后台查看。

### 6.2 水位、晚到消息与重放

重建 `learning_watermarks` 为按归档序号和提炼版本记录进度的新结构；Outbox 继续承担任务投递。周期扫描负责补偿；每次任务可连续处理多个 200 条分页，在达到任务预算后立即投递续跑，不能固定再等 6 小时。旧的发生时间水位不转换成新序号，历史重学使用显式指定的证据区间。

消费顺序应使用每群归档序号 `archive_seq`，事件发生时间只用于语义排序。所有同群归档写入在短数据库事务内取得同一事务锁后分配序号、落库并提交；只有释放锁后下一事务才能分配，避免直接用普通自增 ID 的“先分配后提交”乱序漏洞。重复平台事件保留原序号；实质纠正应以新事实记录进入流。此项需要和负责入站模块的 agent 对齐，不能由学习模块擅自假设已有保障。

提炼前读取一个固定的水位区间；提炼完成后，用预期水位/revision 校验，在同一事务内保存该批声明及证据、投递确认任务、推进水位和安排续跑。另一个 worker 已推进时放弃过期提交并重新读取，不持有数据库锁等待模型。

水位表示“这批事件已完成声明提取”，不表示声明已通过审核。没有新消息时，确认/过期/人工审核任务仍须独立工作。声明与后续任务必须原子落库，避免水位已前进而候选永久无人处理。

重放同一窗口和提炼版本不得重新执行已完成的决定；Outbox 的幂等键与业务唯一键共同保障。需要更换提炼策略重新学习时显式改变版本，仍不得把相同证据重复计数。

## 7. 回忆应按用途装配

保留 RRF 算法和两轨降级能力，由 memory 服务从有效候选装配 `MemoryBundle`。同步修改新 Actor→ResponsePlanner 的真实调用方，删除旧 `RelevantMemories` 契约及未被使用的旧记忆 Prompt 路径，不提供旧返回值适配器。

采用两次有明确目的的读取：决策前按群/目标成员精确读取互动边界，并装配有效 PersonaContext；规则允许参与后，再按本轮完整语义召回长期事实和经历。边界读取不调用向量模型。ResponsePlanner 使用同一回合的人格、场景、完整消息上下文和 Bundle 生成内容，发送前再检查关键约束版本，避免生成期间对方已要求停止。

| Bundle 分区 | 查询方式 | 用途 |
| --- | --- | --- |
| `interaction_boundaries` | 按当前群和目标成员精确读取 | 行动前约束，不能依赖文字相似度或被普通 TopK 挤掉。 |
| `target_user_facts` | 当前主体与本轮问题相关的事实 | 避免忘记称呼、混淆成员偏好。 |
| `group_culture` | 当前话题下的群文化/梗解释 | 帮助理解语境，不强制模仿口癖。 |
| `relevant_episodes` | 当前话题相关的过往事件 | 支持自然续聊和共同回忆。 |

查询优先使用当前 burst 的完整意思、被引用文本和当前话题；“对”“那个呢”不能只按最新两个字检索。素材必须来自运行时上下文，不能为了召回而推测身份或跨群扩大范围。

每个条目携带 memory/claim ID、revision、主体、scope、内容、来源性质、证据引用、有效期和召回原因。预算裁剪按业务优先级与相关性处理，不能把已有排序的记忆列表当时间序列裁剪。角色事实由 PersonaContext 中的解析视图独立提供，保留 verified/canon/reported、来源和定义版本，不能拍平成无来源 map。

所有入口——自动上下文、`query_memory`、主动回忆、后台检索预览——共享相同有效性和可见性过滤。被拒绝、撤销、失效或替代的断言不作为当前事实召回；明确询问历史时，可返回带原有效时间和“已更正”标识的历史版本，revoked 内容仍不可返回。向量表与事实表关联时验证 source revision 一致；缺失或陈旧时走词法轨道。

群友没在相关话题上互动时，不为了证明“我记得”而主动翻出个人信息。主动回忆比被动回答采用更严格的相关性与适用场景判断。

### 7.1 使用统计不能充当事实证据

把现有 recall 拆清含义，优先扩展已有 trace，无需为每种统计新建表：

- `retrieved`：检索返回过，工具试探查询也计入。
- `included`：经过预算裁剪后实际提供给模型。
- `cited`：规划结果声明使用了某条记忆；这只是模型自报。
- `feedback_linked`：成功发送后有可归因的认可、纠正等证据。

只检索到或加入 Prompt 不能增加事实置信度、刷新证据时间或延长 TTL。使用效果也不能自动升级事实真实性；只有新的原始证据或审核决定可以改变事实状态。

## 8. 遗忘、版本与持久化

记忆相关 schema 按目标模型重写。下列名称是目标表，可沿用表名但不保留旧行结构和旧读写接口；不以追加大量可空兼容列替代重建：

| 表 | 调整 |
| --- | --- |
| `messages` | 继续保存证据；补可靠归档顺序，保留事件发生时间；不要求先重命名为 conversation_events。 |
| `memory_claims` | 重建统一声明；主体/事实键、真实有效期、审核原因、revision 和 memory 关联采用新约束。 |
| `memory_claim_evidence` | 新的证据去重和来源角色权威表；旧候选证据表退出运行。 |
| `memory_claim_decisions` | 追加确认、拒绝、替代、撤销及重审决定；支持查询“为什么变成当前状态”。 |
| `memories` | 重建为已确认声明的读取投影；以有效状态、claim 关联和最后证据时间为准。 |
| `memory_vectors` | 从新记忆重新生成；校验源版本，支持失效清理，不导入旧向量。 |
| `learning_watermarks` | 新的归档序号、提炼版本与 revision；删除基于 occurred_at/event_id 的学习游标契约。 |
| `async_outbox` | 保留通用任务设施，新 handler 只接受新 payload；旧学习任务不交给新 handler 解析。 |
| `retrieval_traces` | 新记忆检索使用 included 条目、版本和反馈关联的新契约；旧 trace 仅作历史运维记录。 |

保留原始观察时间，不用任务执行时间把旧事伪装成新近事实。`last_observed_at` 只能由新的有效原始证据更新；索引重建、后台重试和普通读取都不得刷新它。

### 8.1 长期保存、时间有效性和淡出分别建模

长期记忆是核心能力。取消上一版“偏好 90 天、事件 180 天自动过期”的建议；保存时长、事实是否仍适用和常规召回优先级是三件事。

| 内容 | 默认处理 |
| --- | --- |
| 稳定称呼、偏好、身份自述、互动边界 | 长期保存，等待新证据修正或本人撤销；必要时 review_after 提醒复核，复核时间到达不删除。 |
| 重要共同经历、群内故事、角色参与过的事件 | 长期保存；随时间降低默认召回热度，明确问起时仍能按主体/事件检索。 |
| 群梗与群文化 | 保存含义和历史出处；区分“历史上这样用”和“当前仍流行”，活跃度下降不等于事实被抹掉。 |
| “今晚别 @ 我”、本周有事等临时状态 | 设置明确 valid_until；到期不再约束当前行为，历史叙述仍可有来源地保留。 |
| 未确认的弱观察 | staging_deadline 初值可取 7 天，到期结束候选审核；它不是已确认长期记忆的 TTL。 |
| 错误或已替代事实 | 退出当前事实集合，留有来源的纠错历史；明确遗忘的内容按撤销规则处理。 |

自然衰减只调整召回排序，不减少证据强度，不删除重要经历，也不自动恢复已被拒绝的互动方式。默认长期保存用显式无失效时间表达；临时类型缺少有效期或配置解析失败应报错，不静默转成永久保存。是否压缩、归档或物理删除按独立保留策略处理。

遗忘分两步：先在事务中撤销声明、禁用投影并产生清理任务，使所有读取立即失效；再异步清理向量和派生缓存。PromptSession 中已缓存的旧记忆也必须失效或重建，不能只过滤下一次查询。清理与迟到的索引任务使用同一记忆版本/状态检查，禁止已撤销内容被重新索引恢复。

用户明确要求忘记时，还应防止后续重放原始消息再次学回：保存最小的禁止重学标识，排除相应证据，并清理声明、缓存及含内容的任务 payload。保留原始群消息与否由消息保留策略决定；“退出回忆”与“彻底删除原始记录”在后台操作中分别说明，不能把逻辑失效宣传成物理删除。

## 9. 与另一 agent 的接口约定

沿用当前 `ParticipationDecision`、`PersonaContext`、`ResponsePlan`、`ActionFeedback` 的职责划分，直接修订其接口和调用方；新出现的兼容适配器不是必须保留的架构资产。

目标回合顺序如下，调用编排只保留一个所有者：

```text
入站归档、去重、更新当前场景
    → 按目标读取互动边界 + 解析完整 PersonaContext
    → DecisionEngine 决定参与/沉默
    → 参与时：读取 MemoryBundle → ResponsePlanner 调用模型
    → 发送前校验规则、约束版本与 Canon 提案
    → 唯一 Executor → 完整 ActionReceipt
    → 成功出站归档 + Canon 提交 + 持久化反馈窗口
    → 反馈到期任务 → 读取发送后的归因事件 → 保存 ActionFeedback
    → 学习、关系、群姿态/即时状态分别消费同一反馈事实

独立旁路：已归档人类消息 → 窗口学习 → 声明
          无论 Bot 是否回复都继续运行
```

需要对齐的接口最小语义：

| 接口边界 | 必须携带/保证的内容 |
| --- | --- |
| 归档/上下文 → 学习和规划 | 稳定 event ID、可靠归档序号、完整原事件和引用关系、参与者、当前 burst/话题。不能使用当前丢掉 ReplyToMessageID/媒体信息的简化转换代替原事件。 |
| memory → DecisionEngine | 经主体与范围校验的有限 InteractionConstraints、所依赖 memory ID/revision；纠正请求可在当前回合先限制动作。 |
| persona → 决策/规划 | 完整 PersonaConfig、经过有效期归一化的状态，以及经 Canon/ResolveView 裁决并保留来源的事实。决策和规划应使用同一次读取，避免一个看到过期低能量、另一个看到基线。 |
| memory → ResponsePlanner | MemoryBundle 与实际 included 的 memory ID/revision；不能只把记忆塞进已停用的 Composer。 |
| ResponsePlanner → Executor | 受规则约束的动作、可选 Canon 提案、所用记忆 ID/revision；ExpectedOutcome 仅是预期，不可当学习证据。 |
| Executor → 反馈/Canon | 业务 action ID、decision ID、平台 message ID、Sent、实际文本/动作、发送时间、各子动作回执。部分成功只观察实际成功的子动作，失败和沉默不创建发送反馈窗口。 |
| reflection → 各消费者 | 已持久化的反馈 ID/版本、action/decision/group ID、响应人、证据事件、具体归因理由与 unknown/正向/纠正/拒绝等语义。无关群聊数量不产生 positive。 |

新 Executor 需要承接输出校验、成功出站归档、群场景/冷却更新和 Canon 提交，不再并存两个对外发送所有者。发送意图与反馈任务以稳定业务 ID 关联；平台发送与 PostgreSQL 无法组成一个本地事务，发送成功但回执落库失败要记录待核对状态，不能盲目重发并伪造第二次互动。

反馈查询使用发送后区间 `(sent_at, deadline]`，同秒平台时间需结合归档顺序和引用归属，不凭毫秒时间猜先后。窗口及到期任务落库，通过 Outbox 恢复，替换 goroutine+Sleep。读取失败、进程重启或窗口数据不完整属于未完成/未知，不等于“无人接话”。窗口关闭后到达的明确引用纠正仍应作为新反馈证据处理，不能因超过 30 秒就永久忽略。

当前已经有 `participation_decisions`、`action_feedbacks`、`feedback_windows` 表及仓储方法。优先接通并修订其强类型契约，不另起同义表或 `interface{}` 适配层；此处的 action_feedback 指领域事实，不要求复制一张单数表。

反馈持久化与向学习/关系/状态消费者投递任务在同一事务内完成。每个消费者按反馈 ID/版本独立幂等；记忆只生成声明，关系服务只更新关系投影，角色服务只更新状态。具体 memory 被纠正时需要能追到实际发送中涉及的事实，不能因一条“你说错了”就撤销整份 Bundle。

### 9.1 删除与替换清单

| 删除的旧逻辑 | 目标替代 |
| --- | --- |
| `LearningCandidate`、`LearningCandidateStore`、`learning_candidates`、`learning_candidate_evidence` | 统一 Claim、证据关系和审核决定。 |
| `WriteIntent`、`MarkIntent`、`applyLearning`、业务层任意调用 `UpsertMemory` | 唯一的声明确认事务生成记忆投影；存储写方法只在该事务内部使用。 |
| `extractNgrams`、`topicSuffixes`、`behaviorSignal` 及仅凭 0.7 阈值晋升 | 窗口提炼、原始证据校验和按信息类别确认。 |
| `ThoughtRecord → BehaviorSignal → 长期行为记忆` | 有动作归属和人类证据的反馈输入；技术结果只作观测。 |
| 旧 `group_slang/user_catchphrase/topic_keyword/reaction_pattern/behavior_*` 记忆类型 | semantic/social/episodic 及有限 subtype；旧类型不作为别名接收。 |
| 通用记忆中的 `persona` 类型 | Persona Canon 独立真值和 PersonaContext。 |
| 当前 `ClaimInput`、工具参数与旧 `MemoryRecord` 返回值 | 按主体、scope、事实键和证据定义的新契约；全部调用方一次修改。 |
| `RelevantMemories` 与旧记忆 Prompt 拼接 | 分用途、带版本和来源的 MemoryBundle。 |
| 旧 TTL 类型映射、兼容 payload、过时测试断言 | 新配置、新任务格式和行为验收测试；旧配置启动时明确报错。 |
| `_ = NewAgentPlanner`、noOpDeliberator、模板 ComposeResponse 及两套发送所有者 | 一条消费完整上下文/记忆的真实模型规划和动作链路。 |
| 反馈按事件数推导 sentiment、Sleep 后丢弃结果、未使用的 interface{} 仓储契约 | 发送后归因、持久化窗口与强类型反馈消费。 |

保留不依赖旧语义的算法测试，例如 RRF 排序和跨群不可见测试；把断言“刷词即可学会”“sent 可变成行为记忆”“任意 5 条消息即为 positive”的测试改写成目标行为验收，不通过兼容分支让旧断言继续成立。

反馈到记忆的默认规则：明确纠正指向对应事实；明确拒绝某种互动指向个人边界；感谢或接话可支持一次 episodic 事件。没有回应、话题转移或其他人继续聊天均不推出“对方讨厌我”或“这个群喜欢这种回复”。

## 10. 实施顺序与验收

本次仅修订方案。下面区分既有模块的接线验收与记忆专项实现，不把角色、决策和反馈模块重新列为从零开发。

| 阶段 | 工作与删除项 | 完成标准 |
| --- | --- | --- |
| 前置：新回合链路验收 [已有模块，待补齐] | 接通真实模型和完整 PersonaContext，统一执行/回执/出站归档/Canon 调用；修正反馈区间、归因和落库。与记忆领域重写可并行。 | 主链路确实调用模型；参与、沉默、失败和部分发送均产生正确事实；反馈不把发送前消息或无关群聊算成效果。 |
| P0：长期记忆闭环 [未实施] | 定义新 Claim、证据、确认事务与有效投影，落实长期保存/临时有效期/召回淡出；删除旧候选和直接晋升；同步建立真实 Planner 的 Bundle 读取入口。 | 本人事实可自动确认、自然回忆、纠正和遗忘；没有来源不晋升；一年后仍可回忆重要经历。 |
| P1：约束与纠错接入 [未实施] | 决策前精确读取个人边界，发送前复查版本；接 Canon 的来源与发送后规则；完善证据审核页。 | 同群不同人不串，个人边界不升级全群，已纠正事实不再当当前值，生成期间的停止请求也能生效。 |
| P2：窗口学习与可靠追赶 [未实施] | 实现独立于回复的窗口提炼、可靠归档序号、水位事务和有界续跑；沉默回合也学习。 | 超过 200 条能追赶；晚到事件不漏；模型故障不跳水位；重复窗口不重复累计。 |
| P3：反馈消费与回放 [未实施] | 消费已持久化且归因明确的反馈，按 ID/version 幂等；完成分区预算、included 追踪与中文回放集。 | 纠正只作用于相关事实；重试不重复改变关系/状态；unknown 不晋升成长期判断。 |

第一份可验收结果是 P0 加上真实读取入口：给定一条群友自述，下一次相关对话确实能自然记起，并能被更正或遗忘。完整上线前验收全部阶段及对应前置项；开发中允许暂时禁用未完成的后台学习/反馈消费，不用旧逻辑兜底。不能只新增结构体、表和 Prompt 文本就标记完成。

上线采用一次切换：停止旧记忆相关 worker，终止或排空在途任务，取消旧学习/索引任务；离线归档需要保留的原始证据与人工校验记录；替换 schema、代码、配置和 PromptSession；从新空投影启动并按选定证据范围重学、重建向量。新运行时不读取旧候选、旧记忆或旧向量，也不提供自动回退。人工校验记录如需导入，使用一次性离线脚本进入新声明审核流程，完成后移除脚本，不建设长期迁移适配层。

旧表默认退出目标 schema，旧自动学习结果不要求搬迁。原始消息、人工记录及其他模块数据的清理范围在实施切换时单独明确；本次仅给出方案，不执行数据库删除。

验收用真实群聊的脱敏片段建立小型回放集，并优先覆盖以下情况：

| 用例 | 必须满足 |
| --- | --- |
| 两个用户都说“离谱” | 不共用主体记忆；不自动生成没有含义的长期事实。 |
| 一条消息刷十遍同一短语；或重放同一批任务 | 不按十条独立证据晋升。 |
| A 引用 B 的话、第三人开玩笑、Bot 复述群友原话 | 识别来源，不混淆本人自述、转述和 Bot 输出。 |
| “今晚别 @ 我”与“以后不要戳我” | 一个按日期失效，另一个持续到撤销；都只作用于正确对象。 |
| 偏好更新、同名不同人、跨群同一人 | 主体和作用域不串；单值替代与多值共存正确。 |
| 成员偏好 A→B→A，或历史梗不再流行后被重新提起 | 新的本人证据可以建立新的当前断言；旧证据重放不能复活旧版本；历史经历不会仅因时间推移被抹掉。 |
| 一年后询问重要共同经历；长期边界几个月无人提及 | 仍可召回经历并遵守边界，时间淡出只影响常规排序。 |
| Bot 连续沉默期间群友表达稳定偏好 | 后台仍能提取声明；学习不依赖回复模型调用工具。 |
| A 询问 B 在同群公开说过的偏好；询问 B 在另群的事情 | 前者在来源与披露规则允许时可回忆，后者不可跨群检索。 |
| App 真实组装路径、发送失败/部分成功、进程在窗口期重启 | Planner 确实读取 Bundle；只归档成功动作，窗口可恢复，Canon 不提交未发出的设定。 |
| 旧向量任务晚到、发送会话缓存未清、忘记后重放 | 被替代或撤销的内容不能复活。 |
| 第 201 条消息、晚到旧时间消息、两个 worker 并发、提交中断 | 不漏证据、不倒退水位、不产生重复确认。 |
| 发送后别人聊别的话题，或有人引用并纠正 Bot | 前者为未知/无明确反馈；后者才成为对应事实的纠错证据。 |

质量评估分开看：声明正确率和主体/范围准确率、确认错误率、纠错/遗忘生效情况、Relevant Recall@K 与实际入 Prompt 的正确性、无关记忆占比、学习积压时间和每千条消息模型成本。先记录基线，再据回放调整窗口、TTL 和检索权重；不拿“写入记忆数量更多”当作学习进步。
