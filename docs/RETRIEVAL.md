# 混合检索

记忆和表情包通过 `internal/application/retrieval` 共享候选召回与融合规则。上下文、`query_memory` 和表情包工具使用该入口。

```text
查询与可见性
  → 存储层过滤
  → 词法候选与向量候选并行召回
  → RRF 融合、去重
  → 记忆排序 / 素材回查与过滤
  → 上下文或工具结果
```

## 记忆

权威事实位于 `memories`。可见范围包含 `global`、当前群和当前群内获准成员的个人记忆；显式请求不可见 scope 会返回错误，存储实现同样执行范围与有效期过滤。

词法召回读取可见语料，以进程内 BM25 排序；向量召回通过 pgvector 联接权威记忆表读取。两路候选按记忆 ID 去重并使用 RRF 融合，再结合新鲜度、重要性和置信度排序。候选数量取 `TopK × 5` 与配置下限的较大值。

检索会记录召回次数；携带事件 ID 的查询还会记录候选、两路排名、最终分数、耗时和降级信息到 `retrieval_traces`。进入模型前，记忆再按提示词预算裁剪。

称呼、禁止戳和禁止 @ 等结构化偏好使用 `postgres.Store.GetConstraints` 按当前群及说话人读取，不依赖相似度召回，也不受检索 TopK 截断。

## 表情包

当前自动收藏将素材写入全局池。召回实现支持当前群与全局素材；向量结果先合并为一条按相似度排序的轨道，再与词法候选做 RRF。

`application/meme` 回查素材和描述，只保留已批准素材，并应用情绪、场景、发送冷却和哑弹率规则。初次过滤没有结果且查询非空时，扩大词法候选后重试。`prefer_group_scoped` 开启时优先当前群已有素材，不改变自动收藏写入全局池的行为。

## 词法与向量

[BM25](../internal/search/bm25/bm25.go) 是纯 Go 算法。当前分词保留英文、数字词，并对中文生成单字和相邻双字片段；存储查询扫描可见语料，没有持久化倒排索引。

向量检索为可选能力。配置的 Embedding 维度需与 [Schema](../schema/schema.sql) 的 `halfvec(2048)` 一致；`storage.postgres.vector_dim: 0` 关闭向量组装。未配置 Embedding，或启动探测失败时，向量存储不启用。初始化和探测流程见 [graphs.go](../internal/app/graphs.go)。

索引通过 Outbox 更新，保存源版本以抑制过期投影；支持原子存储接口时，事实和索引任务同事务写入。索引是可重建投影，不能作为事实来源。

## 故障与规模边界

- 任一路召回失败时，可以使用另一条成功轨道；所有可用轨道都失败时返回错误。
- Context 可以在普通记忆检索失败时继续回复；相处约束读取失败会阻止规划。
- BM25 扫描成本随可见语料增长，当前没有大规模倒排索引、reranker 或长文档分块链路。
- 异步向量更新可能滞后；当前没有统一的自动索引修复或全量回填流程。
- 后台可查看并重试 Outbox 死信，但这不代表索引已完整或检索质量已通过真实语料评估。

具体融合与排序以 [retrieval/service.go](../internal/application/retrieval/service.go) 为准，素材过滤以 [meme/service.go](../internal/application/meme/service.go) 为准。
